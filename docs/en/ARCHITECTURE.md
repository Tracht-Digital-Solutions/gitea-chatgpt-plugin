# Architecture

ChatGPT/Codex → Streamable HTTP MCP transport → OAuth identity and scope validation → typed tool service → tenant-bound credential/approval store → Gitea API client → DNS/TLS network policy → the selected Gitea instance.

`auth/identity.ts` validates MCP JWTs. `auth/portal.ts` implements browser authorization-code/PKCE login, Gitea connection setup and human approvals. `security/store.ts` stores per-user/per-instance AES-GCM credentials, active selection, atomic single-use approvals and metadata-only audit entries. `security/network.ts` validates allowed HTTPS bases and all DNS answers, pins a checked address to the TLS socket, caps responses and refuses redirects. `gitea/client.ts` handles bounded API calls, safe errors, pagination and feature-branch checks. `tools/catalog.ts` defines focused Zod schemas/request descriptors; `tools/service.ts` applies scope/tenant/approval checks and credential rotation. `mcp/server.ts` supplies annotations, schemas and OAuth challenges; `app.ts` enforces host/origin and HTTP rate limits.

A separate stateless MCP server is constructed per HTTP request, preventing shared user session state. Identity derives from immutable OAuth issuer/subject, never a client-supplied user ID. Active selection is per user; specify explicit instance IDs for concurrent conversations. Browser sessions/state are short-lived in process memory, while connections and approvals persist in SQLite. One process and one persistent volume are supported; horizontal scaling is outside v0.1.

Every mutation stages canonical arguments and a digest bound to owner, instance and credential revision. A separately authenticated human inspects/approves the payload, after which an identical tool call consumes approval atomically once. Changing credentials invalidates pending write approvals. Failed writes consume approval and are not retried automatically. Gitea's file API atomically creates the file change and its commit; the portal previews replacement content before execution, and clients inspect resulting commit/PR diffs afterward.

All external content remains untrusted. No generic arbitrary HTTP endpoint, shell/Git command execution, force push, runner/admin operation or branch-protection bypass is exposed. Additional modules must preserve these authorization, network and approval boundaries.
