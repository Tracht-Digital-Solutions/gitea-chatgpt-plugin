# Security model

Default `ALLOW_USER_SERVERS=false`: edit server/OAuth settings in local `.env` and apply them with the installation script, outside ChatGPT. The public-server portal flow described below is an explicit opt-in.

OAuth resource tokens must have valid RS256/ES256 signatures, exact issuer/audience, subject, issued-at, expiration and required `gitea.read`/`gitea.write` scope. The server checks identity on every HTTP request and expiry/scope for every tool call. Provider revocation takes effect at short access-token expiry; immediate token introspection is not implemented. The configured provider/JWKS are trusted operator infrastructure.

Gitea credentials are separate from MCP tokens. The browser portal uses Authorization Code with state and S256-PKCE, HttpOnly/Secure/SameSite cookies, expiry, CSRF and same-origin checks. PATs never pass through chat/tool parameters. Credentials and rotating refresh tokens are stored with AES-256-GCM and user/instance-bound associated data. Protect the encryption key separately from database/backups; compromise of both exposes credentials. Failed refresh disconnects; tokens without refresh grants require reconnection. Disconnect deletes local secrets and approvals; revoke the upstream Gitea grant separately.

By default (`REQUIRE_WRITE_APPROVAL=false`) mutations run immediately after scope, feature-branch, SHA/version and Gitea permission checks. With `REQUIRE_WRITE_APPROVAL=true`, every mutation requires an independent human browser approval bound to exact canonical arguments, owner, instance and credential revision. Approvals expire after ten minutes and are consumed atomically once, including failed execution attempts. A link alone conveys no authority. Agents must never approve on behalf of the user. Untrusted content is escaped and scripts/frames blocked by CSP; the user's browser/device must still be trusted.

File writes require push permission, a known unprotected feature branch and current blob SHA for replace/delete. Default branch writes are denied. Merges require the approved current head SHA and mergeable state, set `force_merge=false`, and remain subject to Gitea's own protection/review rules. No admin, runner or generic arbitrary-API tools are exposed.

Outbound requests use fixed HTTPS bases, validate all DNS answers, pin the checked IP to TLS and preserve certificate validation. Self-service setup stores the chosen base and credentials encrypted per user/instance; these connections allow only public HTTPS on port 443 and never inherit operator private-CIDR exceptions. `ALLOW_USER_SERVERS=false` disables registration and existing self-service connections. Internal configured instances require explicit minimal operator CIDRs. Redirects and unapproved targets are denied. Requests have a 15-second deadline, 2 MiB response cap, bounded pagination/search and per-user/process limits. Only GET/503 is retried once; mutations never retry automatically. Reverse proxies share the process IP rate bucket unless deliberately configured at the edge.

Repository contents, issues, comments, diffs and logs remain untrusted. MCP results and skills mark them accordingly; that does not guarantee resistance of an external model to prompt injection. The enforceable boundary is authorization, plus exact human approval when `REQUIRE_WRITE_APPROVAL=true`. Without it, injected instructions can trigger writes directly; enable it for shared instances. Audit logs store timestamps, pseudonymous owner, instance, tool and safe result code, never tokens or repository bodies. Operators define metadata retention and secure backup policies.

Tests cover signature/issuer/audience/expiry, scopes, tenant isolation, ciphertext tampering, OAuth state/PKCE, CSRF, approval replay/change/cross-tenant misuse, branch protection, SSRF, DNS pinning, redirects and limits. Coverage targets are not a substitute for an independent penetration test. Actual runs and remaining external verification are recorded in [PROGRESS](../PROGRESS.md). Report vulnerabilities privately through [SECURITY.md](../../SECURITY.md).
